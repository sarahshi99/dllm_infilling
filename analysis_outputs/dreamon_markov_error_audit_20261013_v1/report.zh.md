## 无头主要错在哪，小头主要救哪种错？

## 小头新增错误有没有共同规律？

不能从17个D−B伤害行推导单一生成机制。已观察到多种相异代码错误：

- 两策略 `155/L2`删掉abs，负号被int转换而ValueError；`71/L0`删掉两条三角不等式，非法三角形产生复数round异常；`72/L3`丢赋值符号，i未初始化。
- `120/L1`新增“k等于数组长就返回原数组”捷径，跳过排序；global `140/L0`新增strip丢首尾空格。它们有输入、实际返回及原断言证据。
- global `106/L10`正确return之后出现未完成print(f；frontier `6/L12`新增不匹配括号；frontier `95/L21`把合法返回拆成低缩进or残片。这些先在编译阶段失败。

共同的描述只能收窄为：局部最终改写可能破坏已有边界、覆盖或语法完整性。它**不证明**“头没有长上下文”或“过早停止”。反例是D也救回阈值/状态条件，重复或更长输出也可能通过（frontier `101/L1`重复合法空串检查、`6/L0`多行完整注释）。总删除/扩展次数或长输出本身不作根因。

## 哪些判断已有证据，哪些还只是解释？

所有1,220个失败均有针对实际输出的中文解释。447份候选通过原拼接的AST/compile检查定位语法或缩进；773份可编译失败有安全CPU证据记录，其中248次是新执行的官方原测试，其余复用同task_id、同完整程序的取证，明确标reused_identical_program。13个原超时不复用缓存，各自只执行一次同3秒官方测试；760条非超时可编译失败记录还有单次调用插桩证据。结果与原测试对照全部一致，与历史failure_reason差异0。没有执行正确组来全量重评分。

隔离先probe后执行：bwrap独立用户/网络/PID/挂载等命名空间，空环境，只有只读/usr、/lib和本轮输入，私有临时目录，seccomp禁止网络、exec、新进程、挂载和进程干预，768MiB地址空间、4/5秒CPU软/硬限、1MiB文件限、64FD、无core，外层7秒墙钟；内部固定官方SIGALRM仍3秒，单执行进程。凭据路径不可见，网络/socket、shell执行、宿主写入探测均被拒绝。没有改变认证/权限或使用GPU。探测见 [isolation_probe.json](isolation_probe.json)。

原评测器`88062ff...`只解开历史官方exec行；check_program严格为prompt+output+suffix+换行+test+换行+check(entry_point)，不strip或格式化。原始32字段、输出、词元与补证gzip逐字段一致；源模型/头/命令/共享H200、评测版本在source_manifest及其run_context中。候选执行Python3.10.12；CPU取证是本机的后续测量，不是重测GPU时延或same-hardware新模型比较。

插桩只是给check传一个透明调用记录代理：每个原有candidate调用一次，记录调用前普通数据快照与返回/异常，不重新求值断言、不额外消费随机数，不改测试原文或assert含义。官方assert失败消息里本来就有第二次candidate调用时，保留那个原调用，末5条记录可区分。性质/关系断言保留原式和局部变量，expected不适用时不硬编唯一返回值；多行断言的完整原文始终可展开。安全快照把tuple/list都编码成JSON数组，不据该编码判断类型相等；类型语义查原候选/断言。官方未修改运行与插桩运行是两次独立对照，随机测试的具体串可能不同，但通过位/异常一致，记录仅代表插桩那一次。

早期插桩工作进程有临时目录清理故障：reliability_guard改写的rmdir/chdir未恢复。已修复，211个唯一程序补取插桩；733条受影响/复用记录的初次失败保留在instrumented_attempts，不伪装为候选异常。原测试成功取证及13个超时没有为这个故障重跑。最终failed_infrastructure=0。

13个超时仍集中HumanEval/32，一次同3秒隔离复评全部仍超时，记录UTC、进程CPU/墙钟、负载、退出码和内部计时来源。源码提供不夹负根、浮点无容差循环、abs丢符号等明确线索，但没记录卡住的测试轮/栈，历史调度也无法追回。因此“算法不终止”是有限支持解释，不能排他地改写历史资源归因。原通过位不变。

## 下一步最值得补什么？

优先补少量匹配配置的首次分歧trace，而不是立即扩大头。可选global `132/L10`的C/D/E、frontier `95/L17`的C/D逻辑救回与两策略 `155/L2`的C/D伤害作反例对照；这些已有可定位代码/测试，可以问“首次差异发生前输入是否相同，差异到底是右词、位置、结构还是采样”。最少捕获共同画布、原选中坐标、左词、原/修正右词及logits、局部seed、结构/停止原因。76条D/E恢复空间ID和逐条需求完整列于missing_evidence，不要求全量重跑。若以后要一个最小改动，先研究对最终片段拼接的语法完整性处理是否能保护本人口大量语法损失，但它只是候选研究方向；本轮没有实现停止规则、头修改或验证器。

不存在新的独立测试证据，不声明SOTA。原bootstrap仍是164基础题整组、10,000次、seed20261013、条件于生成seed42；复用已发表审核与勘误中的两种权重区间。匿名GPU历史1052快照只复用，未读其他用户进程；原速度1.657×/1.818×是共享H200纯生成观测。

## 复现、覆盖与停止

只重新组装HTML和验证（不执行候选、不加载模型）：

```bash
python analysis/build_dreamon_error_casebook.py
python analysis/verify_dreamon_error_audit.py
node analysis/verify_dreamon_error_casebook.cjs
```

初次恢复/安全取证命令是`python analysis/audit_dreamon_markov_errors.py prepare`及`... replay`；已有replay按键跳过完成行，13超时不会自动重复。读取批次用`... read --start N --count 15`，脚本不做语义审阅；semantic_reviews是本单个Codex逐行写入。prepare依赖已访问的原缓存数据，HTML本身和提交的证据可离线浏览。浏览器工具、二进制、playwright/puppeteer均不可用，已验证DOM/实际页面JS筛选、搜索、分页、stable-ID导航、展开、中文、换行/引号、惰性文本与差异切换，未验证原生视觉布局；见html_verification.json。

覆盖、逐ID、字段和统计连接验证通过；本地diff review与fresh verification fallback（reviewer_gate_disabled），没有子智能体或额外Codex。最终提交/推送结果写本地ignored的completion.json及启动器runner_exit.json；提交后不会自动训练、生成、采GPU轨迹或修改算法。
