4. 一到两句直白中文解释，例如“这里应返回列表，却返回了一个整数，后续测试对结果取长度时报错”。这句话必须由实际代码和测试支持，不使用假设性模板填充。
5. 已知什么、未知什么，以及下一步需要哪种最小证据。

第一层标签：可观察的错误表现。
保留原评测器结果，并区分语法/缩进错误、具体运行异常、断言失败、超时、评测基础设施问题、证据不足等。空输出、未消除掩码、疑似截断、异常长度、重复后缀等可以作为独立症状标签；它们不是自动成立的根因。
可使用CPU解析完整程序的语法树、编译检查、代码差异、变量作用域等静态检查。必须复用官方实际拼接规则，不能自创一个拼法造成假错误。
保留多个症状时，明确主分类规则和附加标签，避免把同一失败在“互斥数量表”中重复计数。

第二层标签：对生成机制的解释。
例如头未触发、词元替换和失败存在直接联系、需要更长上下文的猜测、位置选择、结构动作/过早停止、先前错误积累、主模型语义能力、评测环境问题等。
每个判断都要有单独证据等级：
- 直接观察：有原始字段、具体程序执行或匹配轨迹支持这个具体事实。
- 有限支持：证据与解释一致，但还有明确其他解释。
- 待验证假设：需要额外对照或生成过程证据。
- 无法判断：现有信息不足。
不得把“变量名不同”“运算符不同”直接升级为“头缺少上下文导致错误”。前者可能是代码事实，后者仍需机制证据。
markov_enabled_count=0只能说明该次生成未调用头，不自动解释所有失败；总删除次数多也不能直接证明过早删除导致失败。

七、失败测试细节只从已有代码和官方测试取得

参考实现不是唯一正确答案；不能按生成文本与参考文本是否一致判定正确，也不能把首个文本差异直接叫作错误词元。
优先使用已有测试日志。如果官方结果只有“断言失败”等简短信息，可以在CPU上重放已有候选程序的已有官方测试，补充异常位置、失败输入、预期和实际值。
只使用此次已访问的同一诊断人口和原有官方测试，不访问新的封存测试、不额外生成新测试来改变本轮评分。
已确认13次超时均属于HumanEval/32。本次用户授权的逐条错误分析包括：仅对这些已保存输出，在同一固定评测器与原3秒参数下进行一次CPU隔离复评，记录UTC起止、CPU时间/墙钟时间、主机负载、子进程退出码或信号、超时来源；不重新生成，不提高时限来改原成绩。其他失败只有取证需要时复评，避免全部重复执行。先准备好隔离措施再运行；资源或隔离条件不具备时保留未知并继续静态分析。

原passed/failure_reason是不可覆盖的历史字段；复评另存audit_passed、audit_failure_reason、环境与差异。遇到超时或不稳定测试，明确标记，不能把后一次成功偷偷替换成原实验通过。
为取得input/expected/actual而做的测试检查或记录，必须单独保存，确认没有改变断言含义。优先复用已有记录；需要插桩时，只捕获原测试单次求值过程中实际产生的值，不能为记录而第二次调用候选函数、重新求值断言表达式或额外消费随机数。特别检查带副作用、迭代器、可变输入和随机状态的测试。将插桩测试与未修改的原测试结果对照；出现passed不一致时，保留差异，不能使用该插桩记录作确定性错误证据。
性质断言、关系断言、多次调用组成的断言等不一定能表示为单一input/expected/actual；此时明确标“不适用”，显示实际断言、可获得的变量值和异常，不硬编一套输入输出。

所有候选程序执行都必须在既有可用的隔离评测环境中，用单独进程、CPU/内存/墙钟时间限制、临时目录和关闭网络的约束。不得执行候选程序中的任意网络访问、shell命令或系统操作，不向候选程序暴露凭据，不执行用户仓库外的任意脚本。
若当前环境不能提供需要的隔离条件，完成静态检查和已有日志分析，将动态细节标“未安全复评/未知”，不要绕过隔离，也不要因此停止其余全部CPU审计。
CPU复评并发应有上限，不与用户现有实验争抢大量CPU资源；本轮不申请或占用GPU。

八、不要把最终差异当作生成因果

可以展示两份最终输出最先出现的文本/词元差异，但明确它是最终文本中的位置。
生成可能乱序，最终字符串从左往右的第一处不同，不等于生成过程中第一次作出不同决定。
检查有没有既有、可以确证与本轮模型/头/配置/种子/最终输出匹配的过程轨迹；旧轨迹仅同题、同通过率，不足以证明可复用。
本轮主运行在保存前移除了action_trace、step_trace、markov_transitions等过程字段。找不到匹配轨迹时，first_generation_divergence必须标unknown，不能凭最终代码和总计数反推。
如果有匹配轨迹，记录首次分歧之前的共同状态，以及第一次不同的是位置、词元、结构动作还是采样路径。首次分歧后画布已不同，后续差异不能再当作相同输入下的单因素比较。
需要GPU重放才能判断的问题，只列入后续最小补证清单：具体ID、比较组、待验证假设、需要捕获的最少字段。本轮不执行GPU重放，不全量重跑。

九、把可能的改进位置与证据连接起来

每条案例可关联一个或多个“值得检查的层”，但必须注明是假设还是已有支持：
- 小头修正本身：D相对C的改变是否救回或造成错误？
- 给头更多上下文：E成功而D失败提供恢复空间线索，但不自动证明缺上下文是原因。
- 位置选择或覆盖条件：头是否实际触发、该失败位置是否处于覆盖范围？无位置轨迹则不编造覆盖结论。
- 结构动作/停止规则：是否有实际残余掩码、删除/扩展或停止证据？总次数异常只是线索。
- 主模型语义问题：A也失败可提示这一方向，但单种子失败不能证明模型能力上限。
- 评测或资源问题：有无拼接错误、环境依赖、超时、异常不稳定？必须和代码语义错误分开。
总结每类有多少直接证据、有限支持、未知，以及有哪些反例；不能以一个故事替代全量统计。
不得根据错误审计自动修改解码器、换模型、扩大头、重新训练或调参数。

十、交付一个真正能逐条看的HTML和可重算证据

在新的追加目录保存，例如：
analysis_outputs/dreamon_markov_error_audit_<实际日期>_v1/
不要覆盖旧诊断目录。

至少包含：
- source_manifest.json：来源分支/提交、原数据路径/版本、字段、审计版本、复用内容和缺失内容。
- integrity_recheck.json：完整性与原表复核，所有差异。
- per_case_compact.jsonl或CSV：全部10,330条，保留所有输出和必要标量。
- joint_outcomes.csv：每策略32格联合分组、八类主表、行数/基础题数/稳定ID索引。
- paired_recheck.csv：原配对结果与重算差异。
- failure_labels.jsonl或CSV：每条失败的两层标签、证据、未知项、审阅状态。
- official_test_replay.jsonl：仅已有代码CPU复评的证据；没有执行时明确说明。
- gpu_background_summary.json或CSV：已有背景负载的摘要，不伪造缺失时间段。
- casebook.html：可离线打开的单个HTML，不依赖外部CDN，不需要启动服务。
- coverage_audit.json：全量覆盖和遗漏清单。
- report.zh.md：主要发现、反例、证据限制、下一步最小补证。
- missing_evidence.json：所有尚缺证据及获取方式。

HTML首页先说明分组和覆盖率，默认展示至少一组失败的案例。支持按策略、八类主组、五组通过状态、基础题、错误类型、证据等级、审阅状态筛选，并按稳定ID/代码文本搜索。
每条案例能展开看到：题意/前后文、A/B/C/D/E五份原始输出、通过位、可切换的输出差异、具体失败测试或异常、白话原因、可观测事实与机制推测、证据出处、可能要改的层及反例/未知。
不要把很长的推理塞成不可阅读的大表；同题相关行可导航，但所有ID都必须可定位。
所有用户数据/代码都需HTML转义，代码不得作为页面脚本执行。随机抽查筛选、搜索、中文、缩进、引号和多行代码的显示，并核对案例总数。

覆盖审计必须给出：
待审行总数、不同基础题数、各阅读分组数量、各组失败输出数、通过位完整及不完整行数与独立缺证据队列；
已逐条检查、已解释但机制待定、因缺证据仍未知、尚未审阅的数量与ID。
“未知”可以是认真审阅后的合法结果，但“未审阅”不能伪装成“未知”。
任何待审行不得只有一句批量复制的模板；至少列明它实际拥有的证据、已做的检查和为何仍不确定。
若原始证据齐全，应完成全部待审行；若部分缺失，完成其余所有可做内容并列出阻塞，不能只返回几个漂亮案例就声称全量完成。

十一、结论、记录和停止边界

这是反复使用的1033行/164基础题开发与机制诊断人口，不是新独立测试。分别报告行数和基础题数；同题多行不能作为相互独立证据。事后错误类别主要做描述性分析，不用少数案例宣称普遍机制或新的显著性。
明确区分D-B整个启用方案、D-C训练修正、C-B路径变化。E可显示恢复空间，但不是可靠的低成本验证方案，也不是所有可能改进的数学上界。

用直白中文回答：
“无头主要错在哪，小头主要救哪种错？”
“小头新增的错误有没有共同规律？”
“哪些是小头没救、真实重算能救，哪些连逐词也失败？”
“哪些判断已有具体代码和失败测试，哪些只是待验证解释？”
“下一步最值得补哪一项证据或试哪一个最小改动，为什么？”

所有历史结果、原通过位、旧结论和当时的依据保留。只追加带日期的观察、修正说明和后续节点；不要重写早先的研究思路来迎合新结果。
沿用仓库既有提交/推送规则，把紧凑逐行证据、分析代码和单文件HTML提交并推送到新分支，不要再次只推汇总，不上传模型权重和庞大张量。
最终给出分支、提交、结果目录、打开HTML的路径/链接、全量覆盖情况、实际未解决项及复现命令。
本轮完成后停止，不自动启动训练、生成重跑、GPU轨迹补采或任何算法修改。
