## 分工与发送方式

一个执行主控对话就够：它负责唯一公共实现、CPU验证、短暂smoke、tmux启动两个独立质量worker、官方评分、统一计时、分析和Git交付。无需另外创建两个语言模型对话才能并发运行。

如果想让不同对话分别监督两个角色，可用总计三个对话：主控＋nohead监督＋trained监督。额外两个对话只登记、检查和调用统一入口，不再改源码或各自创造worker。主控必须自动启动缺席角色，不能因为用户没有发送额外prompt而停在READY。

- 发到执行主控：master_prompt.zh.md 全文。
- 可选无头监督：nohead_prompt.zh.md 全文。
- 可选有头监督：trained_prompt.zh.md 全文。
- 可同时发送；两个监督角色在公共代码READY前不加载模型。已有本角色进程就接续检查，不重复生成。
- 不需要第4个分析对话。统计与报告由主控CPU流水线自动完成。
