## 已确认的问题与修正

1. **汇总错误已修复**：无头基线曾继承 TV 头的修复率、破坏率及分组改善置信区间。已从原始记录重建 `external_test_comparison.csv`，无头修正量为零；两个头原有主要数值未被改写成更好的结果。
2. **冻结划分确有跨集重复**：规范化代码相同的跨集组 1,239 个、涉及 3,506 条记录；题目文本相同的跨集组 3,102 个、涉及 18,372 条记录。两种口径有交集，不可相加。旧“题目组编号零交集”不足以证明隔离。见 `data_overlap_audit.json` 和 `data_overlap_records.csv`。
3. **HumanEval 候选重叠**：共 80 条候选，训练池 69、验证池 3、测试池 8。其中训练池两条代码在统一入口函数名、移除文档字符串后与 HumanEval/13 的最大公约数参考实现相同；另 78 条仅匹配同名入口的部分测试断言，需要人工核查。最大公约数是常见基础算法，这不证明数据抄自 HumanEval；但原先约定的去重检查漏掉了这些记录。候选清单不能等同于已经进入实际训练的记录。
4. **损失归一化已修复代码，旧权重未重训**：v1 把每个 16 条小批次中的参考答案损失分别平均，再以小批次大小累计；有效参考数量不同时，不等于在整批 128 条的所有有效参考上统一平均。修正代码按整次更新的总记录数和有效参考数分别归一化，最后不足 128 条也按实际数计算。已有权重仍标记 `microbatch_aligned_mean_v1`；新代码为 `optimizer_batch_v2`，不得静默沿用旧优化器状态继续训练并混称同一版本。
5. **完整性报告已修正口径**：文件存在性和记录数现在实际检查；“测试打开一次”只是旧脚本自报的单次调用计数，不能证明跨调用生命周期只打开过一次。此次模型测试新增次数为零。
6. **未来数据准备已修复**：按题目、代码（包括真正用于训练的回答代码）、测试组的连接关系合并后划分；强化文档字符串及 `candidate` 调用名处理。不得覆盖 v1 冻结清单，只能在新版本目录生成。原始池中回答代码与辅助 code 字段不一致为 0。

上述修复没有更改历史权重、随机种子、划分清单或逐条诊断。新增防误操作检查只防止三个具体问题：覆盖已冻结数据、把不同损失定义的优化器恢复为同一训练版本、为了重算报表再次打开模型测试；普通 Git 版本本身无法阻止这些运行时覆盖。

## 保守排除后的敏感性分析

按题目文本、代码文本、去文档字符串后的 Python 语法结构及原测试组建立连接关系。验证记录排除与训练池连接的原题目组；测试记录排除与训练池或验证池连接的原题目组；也排除评估池中的 HumanEval 候选组。排除集合完全由数据内容决定，没有按效果选样本。因为本地缺少实际训练库，采用完整训练/验证候选池，排除比仅看实际训练样本更保守。

验证保留 13,123 条、2,734 个重新合并的组；测试保留 13,387 条、2,746 个重新合并的组。置信区间按重新合并后的题目组重采样，10,000 次、seed 20260901；表中距离与一致率为记录级平均。详见 `sensitivity_comparison.csv`、`sensitivity_excluded_problem_groups.json`、`sensitivity_group_map.json.gz`。

| 方法 | 记录数 | TV 距离 | 相对缩小 | 最高概率词元与刷新模型一致 | 修复 / 破坏 |
|---|---:|---:|---:|---:|---:|
| 无头 | 13387 | 0.066839 | 0.00% | 96.489% | 0 / 0 |
| TV 头 | 13387 | 0.048999 | 26.69% | 97.214% | 165 / 68 |
| KL 头 | 13387 | 0.048265 | 27.79% | 97.273% | 160 / 55 |

两个头的分组 TV 改善置信区间下界仍大于零。结果支持“改善并未随这些嫌疑记录的排除而消失”，但这是**测试已打开后的敏感性分析，不是新的独立测试**，也不能证明所有语义相似题都被排除。

继续保留原验证规则选出的 KL 头和 λ=1，不根据这次重算重新选择头或参数。早、中、晚阶段结果另见 `generation_stage_comparison.csv`；原库三个阶段近乎等量，因此总体数值不代表自然解码过程中的阶段占比。
